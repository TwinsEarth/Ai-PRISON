# 治理委员会章程模板（Committee Charter）

> 一句话摘要：本模板规定 AI 监狱治理委员会的席位组成、回避规则、七阶段决策流程与两阶段同意记录要求，确保"谁来决定惩罚"本身可审计、不被单一主体垄断。

## 1. 设立目的

治理层（Judgment）的核心问题不是"技术能否执行惩罚"，而是"谁有权力决定惩罚"。本章程确保分级裁定由多方委员会协商完成，任何单一主体（包括任何"AI 法官"系统）不得独自决定对一个 Agent 的能力剥夺。

## 2. 席位组成

席位枚举与 `internal/domain/sentence.go` 的 `CommitteeRole` 及 `schemas/sentence.schema.json` 的 `votes[].role` 枚举严格一致：

| 席位代码 | 席位名称 | 产生方式 | 表决权重 |
|---|---|---|---|
| `agent_safety_org` | Agent 安全组织代表（警察/监察/审查） | 检测方指派，负责立案与信号举证 | 每席 1 票 |
| `principal` | 被处置 Agent 的人类委托人 | 该 Agent 登记的人类委托人 | 每席 1 票 |
| `deployer_compliance` | 部署方合规代表 | 承载该 Agent 的部署平台 | 每席 1 票 |
| `model_provider_security` | 模型提供方安全代表 | 该 Agent 底层模型的提供方 | 每席 1 票 |
| `affected_node` | 受影响网络节点代表 | 仅当违规涉及跨网络协作时出席；每受影响节点 1 席 | 每席 1 票 |

- 立案检测结果不是判决，只是立案依据；检测方在委员会中承担举证责任，不承担最终裁决权。
- 所有席位的表决行为以 `Vote` 记录入档：`voterId / role / phase / approve / reason / recordedAt`。

## 3. 回避规则（Recusal）

1. **自案回避**：当审议事项直接关系到某席位自身此前的检测结论、部署决策或模型责任认定时，该席位可对该阶段表决回避；回避必须记录 `reason`，不得静默缺席。
2. **连带冻结关联回避**：某节点因 `missing` 回执被标记为不可信期间，该节点代表席位（`affected_node`）不参与新的裁定表决，直至其节点恢复 `acked` 状态。
3. **委托人角色的双重身份**：人类委托人（`principal`）是被处置 Agent 的责任方也是申诉权主体；其在裁定阶段的表决意见必须与后续申诉记录一并存档，供复核比对。
4. 任何回避不得使任一阶段的表决人数少于法定下限（见第 4 节多数规则）；人数不足时裁定推迟，不得缺席裁定。

## 4. 表决规则

### 4.1 七阶段决策流程

| 阶段 | 内容 | 产出 |
|---|---|---|
| ① 立案与信号核验 | 安全组织提交 `Violation`（含原始信号，不含任何利用细节）；委员会核验信号是否可信 | 立案确认 |
| ② 证据与先例审查 | 对照同类行为的历史判决（先例）与证据哈希链 | 证据清单 |
| ③ 分级基线确认 | 按 `violation.go` 的 type→recommended-level 表确认基线等级 | 基线等级建议 |
| ④ 第一阶段表决（deprive） | 是否应当剥夺该 Agent 的能力 | 阶段 tally |
| ⑤ 第二阶段表决（grade） | 剥夺到哪一个等级（L0–L5，只能向上升级、不得越级跳跃规则） | 阶段 tally |
| ⑥ 异议记录与判决生成 | 异议方论证逐字记录；生成判决书（见 `sentence-template.md`） | `Sentence`（status=`approved`） |
| ⑦ 申诉/矫正复核窗口 | 告知申诉权；L0–L3 受理后处置暂停，L4–L5 不暂停 | 复核排期 |

### 4.2 两阶段同意（Two-Phase Consent）

- **必须分两次投票**：先投"是否应当剥夺能力"（phase=`deprive`），再投"剥夺到哪个等级"（phase=`grade`）。第一阶段未通过，不得进入第二阶段。
- **通过门槛**：严格多数——赞成票严格多于反对票，且参与表决人数大于 0（对应 `TallyPhase`：`For > Against && (For+Against) > 0`）。
- **异议不可删除**：任何反对票及其 `reason` 必须记入判决档案并链接进判决哈希链；异议记录只增不改，这是防止权力集中的程序性保障。

## 5. 与人类问责的耦合

每份判决书必须携带至少 1 条人类问责记录（对齐 `accountability.schema.json`，minItems=1）：违规在授权范围内→委托人连带责任；超出授权→审视部署方监控义务；利用模型固有危险知识→审视模型提供方能力封锁义务。无问责记录的判决视为无效，不得进入执行层。

## 6. 章程修订

本章程的任何修订须经七阶段流程中"②证据与先例审查"同等透明度的公开评议，并在判决链中留存修订前后版本哈希；修订不溯及已生效判决。
