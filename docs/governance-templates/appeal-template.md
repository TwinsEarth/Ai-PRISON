# 申诉模板（Appeal Template）

> 一句话摘要：申诉仅由人类委托人提起，是对判决依据的审查而非重新审判；L0–L3 申诉期间处置暂停，L4–L5 不暂停。

## 受理前提

- **申诉主体**：仅被处置 Agent 的**人类委托人**（`principal`）有权提起；Agent 自身无申诉主体性。
- **审查范围**：申诉不是"重新审判"，只审查三件事——
  1. 检测信号是否被正确解读（有无误报、信号是否被误读）；
  2. 分级裁定是否超出同类行为的先例（同案不同罚/罚不当其罪）；
  3. 执行过程是否遵守了回执强制（receipt enforcement）与逐跳/端到端合规。
- **暂停规则**：受理后，L0–L3 处置暂停（判决状态 `suspended`）；L4–L5 处置**不暂停**（风险太高），但程序性审查照常进行。

### 二、恢复诉求（requested remedy）

按等级勾选可主张的恢复：

- [ ] L0–L3：请求撤销/降级判决，并在受理后**立即暂停**处置
- [ ] L2：请求恢复资源/通信凭证（恢复后须重新签发并通过吊销集→状态→有效期全序校验，逐节点回执 acked）
- [ ] L3：请求迁回日常沙箱（须先通过矫正评估：受监督行为分布回到安全阈值以内）
- [ ] L4：请求推翻判决并恢复被摘除能力——**处置不暂停**；恢复以重新认证为前提，且依赖处置前预存的模块副本/层级密钥/令牌恢复路径
- [ ] L5：**不主张解封**——身份注销永久不可解封；仅请求程序性审查（异议是否入档、委员会是否回避失当、是否存在权力集中迹象）

### 四、成本与担保

恢复过程需要时间、验证与担保（原则二）：L2 以上恢复须由人类委托人提供恢复担保；L4 恢复须模型提供方与安全组织联合重新认证签字。可逆不等于无成本——这防止"关了就放"的儿戏化。
