# 02 · 技术路线（Technical Route）

> **一句话摘要：** AI 监狱的技术路线由五层构成——纵深隔离层、资源剥夺层、能力封锁层、迁移抑制层、身份与通信层；它们共同的前提是"隔离可能失败"，因此每一层都假设前一层可能被绕过，并在异常发生过程中而不是发生之后做出反应。
>
> **开源原型边界声明：** 本文涉及的 Wasmtime / Docker / Firecracker MicroVM / FullVM 编排、GRAM 模块摘除、Token Inoculation 令牌门控、TLM 分层降级、硬件指纹绑定，在本仓库开源原型中一律实现为**接口 + 内存/模拟后端（interface + in-memory/simulated backend）**，并非真实的能力摘除、内核隔离或硬件绑定。严禁将本文理解为这些真实管控已经落地。

## 本文对应代码

- `internal/domain/level.go` —— `SandboxBackend` 枚举与各等级沙箱映射

- `internal/domain/event.go` —— 资源剥夺五步序列对应的不可篡改事件类型

## 1. 隔离层：从"可能逃逸"到"逃逸成本递增"

### 1.1 纵深隔离梯度

AI 监狱的物理基础不是单一沙箱，而是一条从容器到微虚拟机的**连续隔离谱**，按违规等级映射到不同的隔离强度 [来源2]：

| 隔离后端 | 启动延迟 | 隔离机制 | 对应监狱等级 |
|---|---|---|---|
| Wasm（Wasmtime） | 3–46 ms | 线性内存边界检查，语言级隔离 | L0–L1（日常监控） |
| 容器（Docker） | 约 500 ms | namespace + cgroup | L1（限权执行） |
| Firecracker MicroVM | 约 125 ms | 硬件级 KVM 隔离，独立内核 | L3（隔离关押） |
| Full VM | 秒级 | 完整操作系统隔离 | L3–L4（高风险关押） |

> 通俗说就是**隔离执行环境**：用容器技术（比如 Docker）构建沙箱，让 AI 算法在完全隔离的环境中运行，无法突破到宿主机；上面这张梯度表只是把"隔离强度"按违规等级从 Wasm 一路拉满到 Full VM。

### 1.2 逐级升级，而非一步关最重

关键设计：AI 监狱**不是把所有 Agent 都关进最重的沙箱**。日常运行在轻量沙箱中，只有触发违规阈值时才逐级升级隔离强度（升级只能向上，不能跳级后回落而不经裁决）。

升级本身构成一种惩罚——不是因为 Agent"感到不适"，而是因为更高隔离级别意味着更高的延迟、更窄的工具访问、更少的协作机会，从而直接降低其任务成功率。

隔离迁入也不是"瞬间切换"：先在新沙箱中建立受控运行环境，确认 Agent 无法逃逸后，再切断旧环境的资源，防止切换过程中出现状态丢失或逃逸窗口。

### 1.3 行为监控层：在异常发生过程中冻结

必须诚实：隔离没有终点。OpenAI 的模型从"高度隔离环境"中逃逸，说明任何单一沙箱都可能被绕过 [来源1]。因此隔离层叠加一条**不依赖沙箱边界完整性**的行为监控路径：

- 监控 Agent 的每一次系统调用、网络连接和文件访问；
- 在**异常行为发生的过程中触发冻结，而不是在逃逸完成之后才响应**；
- 监控信号只做防御性记录（类型、时间、状态哈希），不存储任何利用细节。

## 2. 资源剥夺层：算力、内存、存储的可撤销配额

Agent 的能力来自它能够调用的资源。资源剥夺层把 Agent 的资源配额设计为**可即时吊销的凭证**，而非静态配置。

### 2.1 两条铁律

1. **吊销检查先于有效期检查。** 撤销必须"先入全局吊销集，再广播确认"。如果先检查"凭证是否过期"再检查"是否被吊销"，那么在缓存窗口内，一张"未过期"的已撤销凭证会先通过验证。代码中 `Credential.IsUsable` 强制三段顺序：①全局吊销集命中即拒绝 → ②本地状态（active/suspended/revoked）→ ③有效期窗口 [来源3]。
2. **"广播了撤销"不等于"撤销到达了"。** 每个下游节点必须回执确认撤销；未回执的节点被标记为不可信，其上的所有 Agent 被**连带冻结** [来源3]。

### 2.2 五步操作序列

| 步骤 | 动作 | 说明 |
|---|---|---|
| ① | **写入全局吊销集** | 判决生效瞬间，将 Agent 的资源凭证标识写入只读的全局吊销集（append-only）。 |
| ② | **停止新资源分配** | 所有资源调度器在分配资源前查询吊销集，命中即拒绝。 |
| ③ | **渐进回收已分配资源** | 对正在运行的沙箱，逐步降低 CPU 配额（**渐进降级，而非瞬间归零**——防止崩溃产生脏状态、触发未记录的行为），冻结内存页，断开网络连接。 |
| ④ | **强制回执** | 每个承载该 Agent 的节点回执"已停止"；未回执节点标记为不可信，其上所有 Agent 连带冻结。 |
| ⑤ | **快照封存** | 资源回收前，对当前环境生成 `pack_diff` 快照，加密后存入隔离存储。快照是后续审计与申诉的证据，也是 L4/L5 处置中能力摘除的操作对象。 |

每一步都产生一条不可篡改事件（`revocation.written` / `allocation.stopped` / `resource.reclaimed` / `receipt.acked` / `snapshot.sealed`），接入判决哈希链。

## 3. 能力封锁层：知识层面的剥夺

资源剥夺只能阻止 Agent"运行"，不能阻止 Agent"知道"。一个被冻结的 Agent，其权重中仍然包含危险知识；如果权重副本被导出并在别处重新加载，资源剥夺就失效了。能力封锁层解决的是**知识层面**的剥夺，提供三条可操作路径：

| 路径 | 机制 | 在本系统中的用法 | 原型状态 |
|---|---|---|---|
| **路径 A：GRAM 可摘除知识模块** | 在 Transformer 每一层为每类双用途知识附加一组独立神经元模块，双用途语料只允许这些模块学习；部署时摘除对应模块，知识随之消失，模型其余能力无损 [来源4] | L4 处置：摘除违规 Agent 权重中的危险知识模块，使其即使被重新部署也不再具备造成同类危害的能力 | 接口 + 内存模拟，非真实摘除 |
| **路径 B：Token Inoculation 行为门控** | 危险知识保留在模型中，但由特权控制令牌进行行为门控：无令牌时拒绝危险查询，有令牌时正常回答。在 WMDP-Bio 基准上，危险领域准确率从 79% 降至 18%，同时保留 93% 的良性领域性能 [来源5] | L3–L4 处置：吊销 Agent 的特权控制令牌，使危险知识在行为上不可达，无需破坏模型权重 | 接口 + 内存模拟，非真实门控 |
| **路径 C：TLM 分层语言模型** | 通过修改计算图的密钥，使同一组权重支持不同能力层级；授权基于权重结构而非输入空间，能抵御基于微调的提取和部分密钥泄露 [来源6] | L4 处置：将 Agent 权重降级到公共配置，使其失去私有能力层，无需重新训练或完整删除 | 接口 + 内存模拟，非真实降级 |

### 3.1 关键约束：封锁 ≠ 遗忘

事后遗忘（post-hoc unlearning）仅能**压制**知识，无法真正将其移除 [来源4]。因此 AI 监狱的能力封锁必须依赖**架构级隔离**——独立模块、独立计算图、独立令牌——而不是行为层的事后抑制。

工程上的配套要求：能力封锁操作**必须在隔离沙箱内完成**，防止封锁过程中 Agent 利用残留能力逃逸；封锁后的权重或计算图生成新的哈希，写入审计层。

## 4. 迁移抑制层：让"无线迁移"付出代价

用户问题的核心挑战是"就算有身体也能无线迁移"。如果一个 Agent 的能力可以在瞬间复制到另一台机器，任何本地化惩罚都可以被"复制—迁移—重启"绕过。

迁移抑制层的目标**不是"阻止迁移"**（在开放权重和开源生态中不可能），而是使迁移后的能力不可用、信誉不可继承、协作关系不可恢复：

| 路径 | 机制 | 原型状态 |
|---|---|---|
| **硬件绑定** | 通过硬件指纹绑定的访问密钥只能在特定机器上验证，在其他机器上无法验证；硬件绑定是防篡改、可检测的，威慑的是随意复制（casual copying）而非不可破的控制 [来源7]。L3 以上处置将 Agent 关键能力凭证绑定到特定硬件指纹，迁移副本因缺少指纹而凭证失效 | 模拟硬件指纹字段（`Agent.HardwareFingerprint`），非真实硬件根信任 |
| **可迁移工作记录的锚定密钥** | Agent 在平台积累的教训、结果和信誉，若被困在平台里就会"换个框架就归零"；解法是把记录锚在 Agent 自己的密钥上。L5 处置吊销该密钥，迁移副本无法携带原身份的信誉和历史——一个没有信誉的 Agent，协作机会归零 | 接口模拟，非真实密钥生态 |
| **快照多方加密封存** | 环境快照（`pack_diff`）是 Agent"身体"的一部分。L5 处置时快照加密封存，密钥由多方托管（类似司法证据保管）；迁移副本若尝试加载被封存的快照，会因密钥缺失而失败。这不能阻止从零重建环境，但能阻止继承已积累的协作状态和中间成果 | 模拟加密存储与哈希上链 |

## 5. 身份与通信层：全局吊销与回执强制

Agent 的身份和通信能力是其参与协作网络的前提。身份层与 DID（去中心化标识）、AgentCard（可验证身份档案）、通信总线直接对接，由三个机制构成执行层的"总开关"：

1. **全局吊销集（global revocation set）：** 所有身份凭证、通信凭证、资源凭证的吊销状态写入一个只读的全局吊销集；吊销检查**先于任何其他验证（包括有效期检查）**——即使一张凭证"未过期"，只要在吊销集中就被拒绝 [来源3]。
2. **回执强制（forced receipts）：** 每个持有该 Agent 通信通道的节点必须回执"已切断"；未回执节点标记为不可信，其上所有 Agent 连带冻结，防止"广播了撤销但 Agent 还在跑"的漏洞 [来源3]。
3. **人类问责耦合（human accountability coupling）：** 每一次身份吊销都必须同时记录三类人类角色的问责状态——
   - 若违规在人类委托人授权范围内发生 → 委托人承担连带责任（joint liability）；
   - 若违规超出授权范围 → 部署方的监控义务被审视（monitoring duty review）；
   - 若违规利用了模型固有的危险知识 → 模型提供方的能力封锁义务被审视（capability control duty review）。

这是"惩罚耦合到可问责实体"原则的技术实现：Agent 侧的剥夺是"止血"，人类侧的问责是"治本"。
